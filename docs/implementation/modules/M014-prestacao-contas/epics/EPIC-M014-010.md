## Contexto

A prestacao de contas depende dos movimentos bancarios diarios da conta do projeto e dos dados orcamentarios oficiais para permitir a conciliacao entre movimentacoes financeiras, rubricas autorizadas e despesas declaradas. Atualmente, quando esses dados nao sao importados de forma estruturada, a Area Tecnica precisa conferir manualmente saldos, lancamentos, rubricas e periodos, aumentando risco de erro e retrabalho.

Este EPIC isola as importacoes necessarias para iniciar e conferir a prestacao de contas no modulo M014. Primeiro, o projeto e seus dados bancarios precisam ser sincronizados para criar o `ProjetoRef`, o identificador bancario e a `ContaBancaria` obrigatoria. Depois disso, o importador bancario executa diariamente em uma maquina dedicada, le arquivos CNAB 240 disponibilizados pelo sistema bancario e gera `TransacaoFinanceira` vinculadas a `ContaBancaria`; o orcamento planejado importado do SIGFAPES alimenta o valor total do projeto e a estrutura hierarquica de `RubricaOrcamentaria` usada para classificacao, conciliacao e analise das despesas.

## Objetivo

Permitir que jobs de integracao importem dados de projeto com conta bancaria, executem uma carga unica do orcamento planejado do projeto e importem movimentos bancarios diarios em CNAB 240, garantindo que transacoes financeiras, valor total, rubricas e subrubricas estejam disponiveis para conciliacao com as justificativas de despesa.

## Entidades

- `ProjetoRef` — projeto externo com identificador bancario usado na conciliacao com CNAB 240
- `ContaBancaria` — conta bancaria obrigatoria do projeto, usada como origem dos movimentos CNAB 240
- `TransacaoFinanceira` — movimentos bancarios importados a partir do CNAB 240
- `Orcamento` — valor total planejado do projeto, incluindo valores previstos por agrupamento orcamentario
- `RubricaOrcamentaria` — rubricas e subrubricas importadas do SIGFAPES para estruturar Bolsas, Capital e Orcamento Livre
- `Prestacao` — agregado que utiliza as transacoes para conciliacao e submissao

Ver [modelo-estrutural.md](../modelo-estrutural.md)

### US-M014-037: Importar Projetos e Dados Bancarios

Como sistema de integracao,
quero sincronizar periodicamente os projetos e seus dados bancarios,
para que cada projeto possua `ProjetoRef`, identificador bancario e `ContaBancaria` obrigatoria antes da importacao dos movimentos CNAB 240.

```gherkin
Funcionalidade: Importar Projetos e Dados Bancarios

  Cenario: Sincronizacao com sucesso
    Dado que existe um projeto ativo no sistema de origem
    E o projeto possui identificador bancario e dados de conta bancaria
    Quando o job de sincronizacao de projetos e dados bancarios e executado
    Entao o sistema cria ou atualiza o ProjetoRef
    E registra o IdentificadorBancario do projeto
    E cria ou atualiza a ContaBancaria vinculada obrigatoriamente ao ProjetoRef
    E registra a execucao do job no historico (RN09)

  Cenario: Projeto sem dados bancarios
    Dado que existe um projeto no sistema de origem
    E o projeto nao possui banco, agencia, conta ou identificador bancario
    Quando o job de sincronizacao e executado
    Entao o sistema nao marca o projeto como apto para importacao CNAB 240
    E registra a pendencia no log do job para tratamento operacional

  Cenario: Atualizacao de dados bancarios existentes
    Dado que o ProjetoRef ja possui ContaBancaria vinculada
    Quando o sistema de origem retorna dados bancarios atualizados
    Entao o sistema atualiza a ContaBancaria mantendo o vinculo com o ProjetoRef
    E preserva as TransacaoFinanceira ja importadas
    E registra a alteracao no historico
```

**Definition of Done**

- [ ] Job periodico de sincronizacao de projetos e dados bancarios
- [ ] Criacao/atualizacao de ProjetoRef com IdentificadorBancario
- [ ] Criacao/atualizacao de ContaBancaria obrigatoria por projeto
- [ ] Logs para projetos sem dados bancarios ou dados inconsistentes
- [ ] Testes cobrindo criacao, atualizacao e ausencia de dados bancarios
- [ ] CI verde antes do merge

### US-M014-036: Importar Orcamento Planejado do SIGFAPES

Como sistema de integracao,
quero executar uma carga unica do orcamento planejado do SIGFAPES para cada projeto,
para que a prestacao de contas utilize o valor total, as rubricas e as subrubricas oficiais na classificacao e conciliacao das despesas.

```gherkin
Funcionalidade: Importar Orcamento Planejado do SIGFAPES

  Cenario: Carga unica com sucesso
    Dado que o projeto esta cadastrado no ConectaFAPES
    E possui orcamento planejado aprovado no SIGFAPES
    E ainda nao possui Orcamento importado
    Quando a carga unica de orcamento planejado e executada para o projeto
    Entao o sistema consulta os dados oficiais do projeto
    E cria o Orcamento com o ValorTotal do projeto
    E cria as rubricas orcamentarias de primeiro nivel para Bolsas, Capital e Orcamento Livre quando existirem no SIGFAPES
    E registra para cada rubrica o valor planejado, valor executado importado quando houver e saldo disponivel
    E disponibiliza as rubricas para classificacao dos ItemDocumentoFiscal
    E marca o orcamento planejado como importado para evitar nova carga automatica
    E registra a execucao da carga no historico (RN09)

  Cenario: Importacao de rubrica com subrubricas
    Dado que o SIGFAPES retorna a rubrica "Bolsas"
    E a rubrica possui subrubricas planejadas por modalidade ou finalidade
    Quando o sistema importa o orcamento planejado
    Entao cria a RubricaOrcamentaria "Bolsas" como rubrica principal
    E cria as subrubricas como SubRubricas da rubrica "Bolsas"
    E garante que a soma das subrubricas nao ultrapasse o valor planejado da rubrica principal

  Cenario: Importacao de capital com subrubricas
    Dado que o SIGFAPES retorna a rubrica "Capital"
    E a rubrica possui subrubricas planejadas
    Quando o sistema importa o orcamento planejado
    Entao cria a RubricaOrcamentaria "Capital" como rubrica principal
    E cria as subrubricas como SubRubricas da rubrica "Capital"
    E usa essa hierarquia para classificar aquisicoes de bens e equipamentos

  Cenario: Tentativa de importar orcamento ja carregado
    Dado que o projeto ja possui Orcamento importado do SIGFAPES
    Quando a carga unica de orcamento planejado e executada novamente para o projeto
    Entao o sistema nao altera o Orcamento nem as rubricas orcamentarias existentes
    E registra no log que a carga foi ignorada por ja ter sido concluida anteriormente

  Cenario: Projeto sem orcamento encontrado no SIGFAPES
    Dado que o projeto esta cadastrado no ConectaFAPES
    Quando a carga unica de orcamento planejado e executada para o projeto
    E o SIGFAPES nao retorna orcamento planejado aprovado para o projeto
    Entao o sistema nao cria Orcamento nem RubricaOrcamentaria
    E registra no log da carga que nao ha orcamento planejado aprovado disponivel para importacao

  Cenario: Falha de comunicacao com o SIGFAPES
    Dado que a carga unica de orcamento planejado esta em execucao
    Quando o SIGFAPES fica indisponivel ou retorna erro tecnico
    Entao o sistema nao altera os dados orcamentarios existentes
    E registra a falha no log da carga
    E permite nova tentativa, pois a carga ainda nao foi concluida com sucesso
```

**Definition of Done**

- [ ] Integracao ou adaptador de importacao do orcamento planejado do SIGFAPES
- [ ] Carga unica por projeto, sem execucao recorrente apos sucesso
- [ ] Logs de execucao, falha e tentativa ignorada por carga ja concluida
- [ ] Regras de criacao de Orcamento com ValorTotal do projeto
- [ ] Regras de criacao de RubricaOrcamentaria hierarquica para rubricas e subrubricas
- [ ] Recalculo inicial de saldo por rubrica e subrubrica apos importacao
- [ ] Testes cobrindo carga unica com sucesso, rubricas com subrubricas, projeto sem orcamento, tentativa repetida e falha de comunicacao
- [ ] CI verde antes do merge

### US-M014-001: Importar Movimentos Bancarios CNAB 240

**Depende de:** US-M014-036 (Importar Orcamento Planejado do SIGFAPES)

Como sistema de integracao bancaria,
quero executar diariamente um importador de arquivos CNAB 240 disponibilizados pelo sistema bancario,
para que o sistema possa conciliar as despesas declaradas com as movimentacoes bancarias.

```gherkin
Funcionalidade: Importar Movimentos Bancarios CNAB 240

  Cenario: Execucao diaria com sucesso
    Dado que o sistema bancario disponibilizou arquivo CNAB 240 na maquina de integracao
    E o orcamento planejado do projeto ja foi importado do SIGFAPES
    Quando o importador diario processa o arquivo
    Entao o sistema identifica o projeto pelo identificador bancario quando informado no arquivo
    E identifica banco, agencia, conta, data de movimento e lancamentos
    E classifica cada TransacaoFinanceira como DEBITO ou CREDITO conforme o CNAB 240
    E persiste as TransacaoFinanceira vinculadas a ContaBancaria correspondente
    E garante que a ContaBancaria esteja vinculada ao ProjetoRef do projeto
    E registra saldo inicial, saldo final e data de processamento quando disponiveis no arquivo
    E registra a execucao do importador no historico (RN09)

  Cenario: Transacao de debito importada
    Dado que o arquivo CNAB 240 possui um lancamento de debito
    Quando o importador diario processa o lancamento
    Entao cria uma TransacaoFinanceira com Tipo = DEBITO
    E deixa a transacao disponivel para conciliacao com justificativas de despesa

  Cenario: Transacao de credito classificada como estorno
    Dado que o arquivo CNAB 240 possui um lancamento de credito
    E existe uma TransacaoFinanceira de debito ja importada para a mesma conta bancaria
    E o debito possui o mesmo valor do credito
    E o debito possui a mesma fonte do credito
    Quando o importador diario processa o credito
    Entao cria uma TransacaoFinanceira com Tipo = CREDITO
    E classifica o credito na rubrica "Estorno"
    E vincula o credito ao debito correspondente para indicar a compensacao

  Cenario: Transacao de credito classificada como rendimento
    Dado que o arquivo CNAB 240 possui um lancamento de credito
    E o lancamento foi originado pelo banco como rendimento financeiro da conta
    Quando o importador diario processa o credito
    Entao cria uma TransacaoFinanceira com Tipo = CREDITO
    E classifica o credito na rubrica "Rendimento"
    E disponibiliza o rendimento no balanco do projeto conforme regra orcamentaria aplicavel

  Cenario: Transacao de credito sem regra de classificacao automatica
    Dado que o arquivo CNAB 240 possui um lancamento de credito
    E o credito nao corresponde a estorno
    E o credito nao foi identificado como rendimento bancario
    Quando o importador diario processa o credito
    Entao cria uma TransacaoFinanceira com Tipo = CREDITO
    E marca a transacao como pendente de classificacao operacional
    E registra a ocorrencia no log do importador

  Cenario: Arquivo CNAB 240 sem conta bancaria correspondente
    Dado que o importador diario esta processando um arquivo CNAB 240
    E o arquivo contem banco, agencia, conta ou identificador bancario de projeto nao cadastrados no ConectaFAPES
    Quando o sistema tenta associar os lancamentos a uma ContaBancaria
    Entao nao cria TransacaoFinanceira para essa conta
    E registra a ocorrencia no log do importador para tratamento operacional

  Cenario: Reprocessamento idempotente do mesmo arquivo
    Dado que um arquivo CNAB 240 ja foi processado anteriormente
    Quando o importador diario processa novamente o mesmo arquivo
    Entao o sistema nao duplica TransacaoFinanceira ja importada
    E registra no log do importador que o arquivo foi reprocessado sem duplicidade

  Cenario: Arquivo CNAB 240 invalido
    Dado que o sistema bancario disponibilizou arquivo fora do leiaute CNAB 240 esperado
    Quando o importador diario tenta processar o arquivo
    Entao o sistema rejeita o arquivo
    E nao altera os lancamentos bancarios existentes
    E registra a falha no log do importador
    E agenda nova tentativa ou tratamento manual conforme politica operacional
```

**Definition of Done**

- [x] Importador diario executando em maquina de integracao
- [x] Parser CNAB 240 com validacao de leiaute e associacao por banco/agencia/conta
- [x] Regras de classificacao de TransacaoFinanceira em DEBITO e CREDITO
- [x] Regras de credito para rubrica "Estorno" quando houver debito de mesmo valor e mesma fonte
- [x] Regras de credito para rubrica "Rendimento" quando a origem for rendimento bancario
- [x] Testes unitarios cobrindo RN02, idempotencia, classificacao de credito/debito e vinculo TransacaoFinanceira -> ContaBancaria
- [x] Testes de integracao: arquivo CNAB 240 -> persistencia -> logs de processamento
- [x] CI verde
