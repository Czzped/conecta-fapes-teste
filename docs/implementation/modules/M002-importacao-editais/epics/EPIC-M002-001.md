## Contexto

Antes de importar projetos, alocacoes e bolsistas, e necessario que alguem dentro da FAPES defina quais editais do SIGFAPES serao gerenciados no ConectaFAPES. Sem essa selecao, o sistema nao sabe quais editais devem ter seus dados importados e sincronizados. Este EPIC e o ponto de partida do modulo — nenhuma importacao ou complementacao de dados ocorre sem que os editais tenham sido previamente selecionados.

A listagem e alimentada pelos dumps publicados no S3 pelos jobs `scripts/conecta_dump_job.py` (copia Parquets do MinIO do Conecta) e `scripts/sigfapes_dump_job.py` (consome a API HTTP do SIGFAPES com token). O frontend apresenta cada edital com contagem de bolsistas, flag "Novo" (60 dias), status de lock e versoes de planilha existentes.

!!! note "Gatilho Airflow no frontend — pendente"
    O backend ja expoe as rotas de trigger e status (`app/services/airflow_trigger.py`, `app/services/airflow_check.py`), mas o botao no frontend que dispara a DAG `SigFapes2Conecta` sob demanda ainda nao foi implementado. A implementacao depende da maturidade do proprio Airflow — o fluxo do botao ficou como trabalho futuro.

## Objetivo

Permitir que um operador autenticado via Supabase Auth visualize a lista de editais disponiveis no dump SIGFAPES mais recente, filtre por ID/nome, ordene por data ou quantidade de bolsistas, identifique quais editais estao com lock ativo de outros operadores e selecione um edital para abrir o fluxo de correcao.

### US-M002-001: Autenticar Operador

Como operador da agencia,
quero fazer login com email e senha,
para acessar o fluxo de correcao com sessao segura.

```gherkin
Funcionalidade: Autenticar operador

  Cenario: Login valido
    Dado que o operador possui conta Supabase Auth ativa
    Quando informa email e senha corretos na tela de login
    Entao o backend retorna cookies HttpOnly "sb-access-token" e "sb-refresh-token"
    E o frontend redireciona para /editais-latest

  Cenario: Credenciais invalidas
    Quando o operador informa senha incorreta
    Entao o sistema exibe "Credenciais invalidas" sem revelar qual campo esta errado
```

---

### US-M002-002: Listar Editais do Ultimo Dump

Como operador autenticado,
quero ver os editais publicados no dump SIGFAPES mais recente,
para escolher qual editar.

```gherkin
Funcionalidade: Listar editais

  Cenario: Listagem com dump publicado
    Dado que o dump diario foi publicado no S3 com sucesso
    Quando o operador acessa /editais-latest
    Entao o sistema exibe cada edital com numero, titulo, data de cadastro e contagem de bolsistas
    E o backend calcula a contagem consultando bolsistas.parquet

  Cenario: Dump indisponivel
    Dado que os Parquets nao estao acessiveis no S3
    Quando o operador acessa /editais-latest
    Entao o sistema exibe mensagem de erro e instrui a tentar novamente mais tarde
```

### US-M002-003: Sinalizar Editais Novos

Como operador,
quero identificar visualmente editais recentes,
para priorizar correcoes de editais que acabaram de entrar.

```gherkin
Funcionalidade: Flag de edital novo

  Cenario: Edital cadastrado ha menos de 60 dias
    Dado um edital com edital_data_cadastro dentro dos ultimos 60 dias
    Quando a lista e renderizada
    Entao o card do edital exibe o badge "Novo" sem icone de informacao

  Cenario: Edital antigo
    Dado um edital com edital_data_cadastro superior a 60 dias
    Quando a lista e renderizada
    Entao o card do edital nao exibe o badge "Novo"
```

### US-M002-004: Exibir Status de Lock e Planilha Existente

Como operador,
quero saber quando um edital ja esta sendo editado por outro operador,
para evitar conflitos de edicao concorrente.

```gherkin
Funcionalidade: Status de lock e planilha

  Cenario: Edital com lock ativo de outro operador
    Dado que existe um resource_locks ativo para o edital com owner diferente do atual
    Quando a lista e renderizada
    Entao o card exibe o nome do operador que esta com o recurso
    E o botao de abertura vira "Em uso por <operador>"

  Cenario: Edital com planilha corrigida existente
    Dado que existe planilha versao >= 2 para o edital na competencia atual
    Quando a lista e renderizada
    Entao o card exibe a ultima versao e data do upload mais recente

  Cenario: Polling automatico de locks
    Dado que o operador esta na tela de listagem
    Quando passa 10 segundos
    Entao o frontend consulta POST /locks/batch-status e atualiza o status dos cards
```

### US-M002-005: Filtrar e Ordenar Editais

Como operador,
quero filtrar por numero ou titulo e ordenar por data ou contagem,
para encontrar rapidamente o edital desejado em listas com muitos itens.

```gherkin
Funcionalidade: Filtro e ordenacao

  Cenario: Filtro por texto
    Dado uma lista com 200 editais renderizada
    Quando o operador digita "18/2023" no campo de busca
    Entao apenas editais cujo numero ou titulo contem "18/2023" permanecem visiveis

  Cenario: Ordenacao por "Novos"
    Dado uma lista com editais de varias datas
    Quando o operador clica no botao de ordenacao "Novos"
    Entao editais com novo_este_mes=true aparecem primeiro
    E o icone de informacao no botao exibe tooltip explicando o criterio dos 60 dias
```
