## Contexto

Os dados brutos do SIGFAPES vem com inconsistencias sistemicas: bolsistas com `formulario_cancel_bolsa_data` incompativel com `formulario_bolsa_termino`, contas bancarias desatualizadas, niveis de bolsa que precisam ser fatiados em periodos. Este epic entrega o editor colaborativo em que o operador abre a planilha pre-preenchida, edita no navegador com validacao em tempo real, alterna entre os tipos `editais` e `programas` quando necessario e envia a versao corrigida com auditoria completa.

## Objetivo

Entregar o ciclo completo de edicao de uma planilha: aquisicao de lock exclusivo, geracao da planilha inicial a partir dos Parquets, edicao em tela com virtual scroll, validacao de upload, versionamento auditado e alternancia entre tipos `editais` e `programas` com clone da planilha.

### US-M002-006: Adquirir e Manter Lock Exclusivo

```gherkin
Funcionalidade: Lock exclusivo de edicao

  Cenario: Aquisicao bem-sucedida
    Dado que nenhum outro operador possui lock ativo sobre o recurso
    Quando o operador abre o edital para edicao
    Entao o backend cria uma linha em resource_locks com owner atual e retorna lock_token
    E o frontend inicia heartbeat a cada 45 segundos

  Cenario: Recurso ocupado
    Dado que outro operador possui lock ativo nao expirado
    Quando o operador tenta abrir o edital
    Entao o backend retorna 409 com dados do dono atual
    E o frontend oferece opcao de acompanhar o recurso em modo leitura

  Cenario: Takeover de lock expirado
    Dado que existe lock cuja heartbeat_at > 3 minutos atras e expires_at no passado
    Quando outro operador solicita /locks/acquire
    Entao o backend marca o lock anterior como released_at com reason=takeover
    E cria novo lock para o ator atual

  Cenario: Release no unload
    Dado que o operador esta editando
    Quando fecha a aba ou navega para outra pagina
    Entao o frontend emite /locks/release com o lock_token
```

### US-M002-007: Gerar Planilha Inicial do Edital

```gherkin
Funcionalidade: Gerar planilha inicial

  Cenario: Primeira geracao
    Dado que nao existe nenhuma versao de planilha para o escopo (kind, MM_YYYY, edital_id)
    Quando o backend recebe POST /cria-planilha-edital
    Entao realiza 4 GetObject em paralelo nos Parquets e no JSON
    E calcula effective_end, MESES_DE_ATIVIDADE e total_deve_receber via NumPy
    E produz um XLSX com cabecalho, dados bancarios e 5 grupos de colunas de nivel
    E grava v1.xlsx no S3 e registra action=create_initial em planilha_version_audit

  Cenario: Planilha ja existe
    Dado que existe ao menos uma versao para o escopo
    Quando o operador abre a tela de correcao
    Entao o backend retorna a versao mais recente em vez de gerar novamente
```

### US-M002-008: Editar Planilha com Validacoes em Tempo Real

```gherkin
Funcionalidade: Editor de planilha

  Cenario: Virtual scroll com 5000 linhas
    Dado um edital com 5000 bolsistas
    Quando o operador rola a tabela
    Entao apenas linhas visiveis + overscan de 5 sao renderizadas mantendo 60fps

  Cenario: Validacao de data
    Quando o operador digita uma data de cancelamento anterior a data de inicio
    Entao a celula e marcada com borda vermelha e exibe tooltip explicando o erro

  Cenario: Flag dirty
    Dado que o operador alterou uma celula
    Quando tenta navegar para outra pagina
    Entao o navegador exibe aviso de alteracoes nao salvas
```

### US-M002-009: Validar e Enviar Planilha Corrigida

```gherkin
Funcionalidade: Upload da planilha corrigida

  Cenario: Pre-validacao
    Quando o operador clica em "Validar upload"
    Entao o backend compara o arquivo enviado com a versao vigente
    E retorna errors, warnings e diff linha a linha
    E o frontend exibe ValidationSidebar com contagem por severidade

  Cenario: Upload com erros bloqueantes
    Dado que a validacao retornou ao menos um erro
    Quando o operador tenta enviar
    Entao o backend recusa com 422 e lista dos erros
    E nenhuma nova versao e criada

  Cenario: Upload aprovado
    Dado que o operador e dono do lock ativo
    E que a pre-validacao nao encontrou erros bloqueantes
    Quando o backend recebe POST /upload-planilha-corrigida
    Entao grava v{N+1}.xlsx no S3
    E registra action=upload_corrigida em planilha_version_audit com request_id
```

### US-M002-010: Alternar entre Tipos editais e programas

```gherkin
Funcionalidade: Troca de tipo ativo

  Cenario: Clone bem-sucedido
    Dado que a planilha ativa e kind=editais na versao atual
    Quando o operador confirma a troca para programas
    Entao o backend busca a versao mais recente de kind=editais
    E grava copia como v1.xlsx em kind=programas
    E registra action=switch_clone em planilha_version_audit
    E atualiza resource_kind_state.active_kind=programas
    E insere linha em resource_kind_switch_log

  Cenario: Troca sem lock
    Dado que o operador nao possui lock ativo
    Quando tenta alternar o tipo
    Entao o backend recusa com 409
```

### US-M002-011: Configurar Mapeamento de Programas

```gherkin
Funcionalidade: Mapeamento projeto -> Area Tecnica

  Cenario: Abrir ProgramConfigModal
    Quando o operador clica em "Configurar programas"
    Entao o frontend carrega GET /dados-programas
    E exibe lista virtualizada de projetos do edital com campos Area Tecnica e Programa

  Cenario: Salvar mapeamento
    Dado que o operador preencheu todos os projetos
    Quando clica em salvar
    Entao o backend valida que toda Area Tecnica informada existe no catalogo
    E grava dados-programas.json no S3

  Cenario: Mapeamento incompleto bloqueia geracao de JSONL
    Dado que existem projetos sem Area Tecnica informada
    Quando o operador tenta gerar arquivos de importacao
    Entao o backend retorna 422 com lista de projetos faltantes
```
