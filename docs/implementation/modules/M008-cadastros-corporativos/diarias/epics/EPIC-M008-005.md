## Contexto

O fluxo de solicitacao de diarias no M003 depende de valores corporativos e parametros normativos mantidos pela FAPES. O M008 e o dono do cadastro `TipoDiaria`, que define valor unitario, vigencia e abrangencia da viagem, e do cadastro `ParametroCalculoDiaria`, que versiona percentuais, limites, bloqueios e norma de referencia vinculados ao tipo de diaria usado no calculo operacional.

Nao existe cadastro editavel de tipo de viagem. A classificacao da viagem e feita pela classe corporativa `Abrangencia`, com codigos canonicos iniciais `DENTRO_ESTADO`, `NACIONAL` e `INTERNACIONAL`.

Esses dados devem ser administrados em um unico contexto de **Diarias** no back-office, dentro de **Configuracoes > Referencias Corporativas > Diarias**.

## Objetivo

Permitir que a FAPES cadastre, consulte e mantenha valores vigentes de diaria por abrangencia e parametros normativos de calculo vinculados ao tipo de diaria, com controle de vigencia, situacao ativa/inativa, bloqueio de sobreposicao e consulta segura pelo M003 no momento da solicitacao.

## Fora de Escopo

- Solicitar diaria para bolsista ou coordenador, responsabilidade do M003.
- Alocar, debitar, estornar ou prestar contas de diaria, responsabilidades de M003/M013/M014 conforme fluxo.
- Definir saldo de rubrica do projeto.
- Cadastrar tipo de viagem como entidade editavel.
- Alterar snapshots de solicitacoes ja criadas.

## Modelo de Referencia

| Elemento | Papel |
|----------|-------|
| Abrangencia | Classe corporativa que classifica a viagem |
| TipoDiaria | Versiona valor unitario e vigencia para uma abrangencia |
| ParametroCalculoDiaria | Versiona parametros normativos de calculo por TipoDiaria, vigencia e norma de referencia |

## Criterios de Aceite

### US-M008-021: Gerenciar valores vigentes de diaria por abrangencia

```gherkin
Funcionalidade: Gerenciar valores vigentes de diaria

  Cenario: Cadastrar valor vigente
    Dado que o Analista da Agencia esta autenticado
    Quando cadastra o valor unitario 260,00 para a abrangencia "ABR-2026-001" com codigo "DENTRO_ESTADO" e vigencia inicial "2026-05-01"
    Entao o sistema cria um TipoDiaria ativo
    E exibe o valor vigente no contexto administrativo de Diarias

  Cenario: Bloquear valor invalido
    Dado que o Analista esta cadastrando valor de diaria
    Quando informa valor unitario menor ou igual a zero
    Entao o sistema rejeita o cadastro
```

### US-M008-022: Gerenciar abrangencias de diaria

```gherkin
Funcionalidade: Gerenciar abrangencias de diaria

  Cenario: Cadastrar abrangencia
    Dado que o Analista da Agencia esta autenticado
    Quando cadastra a abrangencia com codigo "NACIONAL", nome "Nacional" e situacao ativa
    Entao o sistema cria a Abrangencia
    E ela fica disponivel para cadastro de TipoDiaria

  Cenario: Rejeitar codigo duplicado
    Dado que ja existe a abrangencia com codigo "NACIONAL"
    Quando o Analista cadastra outra abrangencia com o mesmo codigo
    Entao o sistema rejeita o cadastro
```

### US-M008-023: Bloquear vigencias sobrepostas para a mesma abrangencia

```gherkin
Funcionalidade: Controlar vigencia de valores de diaria

  Cenario: Bloquear sobreposicao de periodo
    Dado que existe TipoDiaria vigente para a abrangencia "ABR-2026-001" com codigo "DENTRO_ESTADO" a partir de "2026-05-01"
    Quando o Analista cadastra outro valor para a mesma abrangencia com periodo sobreposto
    Entao o sistema bloqueia o cadastro

  Cenario: Permitir nova vigencia futura sem sobreposicao
    Dado que existe TipoDiaria vigente ate "2026-12-31"
    Quando o Analista cadastra novo valor para a mesma abrangencia com vigencia inicial "2027-01-01"
    Entao o sistema aceita a nova vigencia
```

### US-M008-024: Consultar diaria vigente para consumo do M003

```gherkin
Funcionalidade: Consultar diaria vigente

  Cenario: Retornar diaria vigente
    Dado que o M003 informa abrangencia e data de referencia
    Quando existe TipoDiaria vigente para a abrangencia e a data
    E existe ParametroCalculoDiaria vigente para o TipoDiaria e a data
    Entao o M008 retorna TipoDiaria, ParametroCalculoDiaria, abrangencia, valor unitario, parametros de calculo, norma de referencia e vigencia

  Cenario: Ausencia de valor vigente
    Dado que o M003 informa abrangencia e data de referencia
    Quando nao existe TipoDiaria vigente para a abrangencia e a data
    Entao o M008 retorna erro de diaria vigente ausente

  Cenario: Ausencia de parametros vigentes
    Dado que o M003 informa abrangencia e data de referencia
    Quando nao existe ParametroCalculoDiaria vigente para o TipoDiaria e a data
    Entao o M008 retorna erro de parametros de calculo ausentes
```

### US-M008-025: Ativar e inativar valores de diaria preservando historico

```gherkin
Funcionalidade: Ativar e inativar valores de diaria

  Cenario: Inativar valor vigente
    Dado que existe valor vigente de diaria ativo
    Quando o Analista inativa o valor com justificativa
    Entao o sistema deixa de retorna-lo para novas consultas de vigencia
    E preserva o registro para auditoria
```

### US-M008-026: Auditar alteracoes dos cadastros de diaria

```gherkin
Funcionalidade: Auditar cadastros de diaria

  Cenario: Registrar alteracao
    Dado que o Analista altera valor de diaria ou parametros de calculo
    Quando confirma a alteracao
    Entao o sistema registra usuario, data, entidade alterada, dados anteriores e dados novos

  Cenario: Consultar historico
    Dado que ha alteracoes registradas
    Quando o Analista consulta o historico do cadastro
    Entao o sistema exibe a linha de auditoria do TipoDiaria ou do ParametroCalculoDiaria
```

### US-M008-027: Gerenciar parametros normativos de calculo de diaria

```gherkin
Funcionalidade: Gerenciar parametros normativos de calculo de diaria

  Cenario: Cadastrar parametros vigentes
    Dado que o Analista da Agencia esta autenticado
    Quando seleciona o TipoDiaria "DIA-2026-001" e cadastra parametros com norma "Decreto ES no 5533-R/2023", percentual sem pernoite 0,40, minimo de 6 horas, retorno apos 14h, distancia minima 150 km e limite mensal 15
    Entao o sistema cria ParametroCalculoDiaria ativo vinculado ao TipoDiaria
    E exibe os parametros no contexto administrativo de Diarias

  Cenario: Bloquear parametros sobrepostos
    Dado que existe ParametroCalculoDiaria vigente a partir de "2026-05-01" para o TipoDiaria "DIA-2026-001"
    Quando o Analista cadastra outro conjunto de parametros para o mesmo TipoDiaria com periodo sobreposto
    Entao o sistema bloqueia o cadastro

  Cenario: Consultar parametros por data
    Dado que existem parametros vigentes para o TipoDiaria "DIA-2026-001" em "2026-05-01"
    Quando o M003 consulta parametros por TipoDiaria e data de referencia
    Entao o M008 retorna percentuais, limites, bloqueios e norma de referencia vigentes
```

## Regras de Negocio

| ID | Regra |
|----|-------|
| RN22 | Abrangencia e classe corporativa com codigo canonico unico, nome, descricao e situacao ativa/inativa. |
| RN23 | TipoDiaria deve possuir abrangencia, valor unitario, vigencia e situacao ativa/inativa, sem vigencias sobrepostas para a mesma abrangencia. |
| RN24 | ParametroCalculoDiaria deve estar vinculado a um TipoDiaria e possuir norma de referencia, percentuais, limites, bloqueios, vigencia e situacao ativa/inativa, sem vigencias sobrepostas para o mesmo TipoDiaria. |

## Impactos em Outros Modulos

| Modulo | Impacto |
|--------|---------|
| M003 | Consulta diaria e parametros vigentes por data de referencia ao criar solicitacao; grava snapshot para preservar calculo historico |
| M013 | Usa o valor calculado em M003 para alocar/debitar rubrica do projeto |
| M014 | Pode referenciar a diaria solicitada/prestada, mas nao altera cadastros corporativos |

## Observacoes

- A situacao de `TipoDiaria` e booleana: ativo/inativo.
- A abrangencia e classe corporativa de referencia, com codigo canonico controlado pelo M008.
- A situacao de `ParametroCalculoDiaria` e booleana: ativo/inativo.
- A alteracao de valor, abrangencia ou parametros normativos nao deve recalcular solicitacoes ja criadas.
