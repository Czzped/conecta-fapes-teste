## Contexto

Apos a publicacao da captacao e abertura do periodo de recebimento, proponentes submetem propostas de iniciativas usando o formulario de submissao selecionado no M021. A agencia acompanha as propostas com filtros por area, status e instituicao.

## Criterios de Aceitacao

- Proponente consegue submeter proposta durante periodo de recebimento
- Proposta submetida fora do periodo e recusada automaticamente (RN15)
- Area tecnica consegue listar propostas com filtros por area, status e instituicao
- Proposta registra proponente, data de envio e status

## US-M011-037 — Validar Elegibilidade do Proponente na Submissao

Como proponente ou sistema,
Quero que a elegibilidade do proponente seja validada no momento da submissao,
Para que propostas invalidas sejam rejeitadas antes de entrar na fila de analise.

```gherkin
Funcionalidade: Validacao de elegibilidade do proponente na submissao

  # AX-M011-005: ProponenteEscolhido exists only when RegraSubmissao.submissaoRestritaAEscolhidos = true
  Cenario: Proponente nao autorizado tenta submeter em captacao restrita
    Dado que a captacao possui RegraSubmissao.submissaoRestritaAEscolhidos = true
    E o proponente autenticado nao consta na lista Captacao.proponentesEscolhidos
    Quando o proponente tenta submeter uma proposta para essa captacao
    Entao o sistema rejeita a submissao com a mensagem "Proponente nao autorizado para esta captacao"
    E nenhuma proposta e registrada no sistema

  Cenario: Proponente autorizado submete em captacao restrita
    Dado que a captacao possui RegraSubmissao.submissaoRestritaAEscolhidos = true
    E o proponente autenticado consta na lista Captacao.proponentesEscolhidos
    Quando o proponente tenta submeter uma proposta valida
    Entao o sistema aceita a submissao normalmente

  # AX-M011-013: OutorgadoDestinatario com tipo=PESSOA_FISICA deve ter cpf+nome; cnpj, razaoSocial, contatoPF devem ser nulos
  Cenario: OutorgadoDestinatario PF com campos PJ preenchidos
    Dado que uma captacao do tipo DEMANDA_INDUZIDA esta sendo configurada
    E um OutorgadoDestinatario com tipo = PESSOA_FISICA e cadastrado
    Quando os campos cnpj, razaoSocial ou contatoPF sao fornecidos para esse destinatario
    Entao o sistema rejeita o cadastro com mensagem indicando que campos de pessoa juridica nao sao permitidos para pessoa fisica
    E os campos cpf e nome sao obrigatorios para tipo PESSOA_FISICA

  # AX-M011-014: OutorgadoDestinatario com tipo=PESSOA_JURIDICA deve ter cnpj+razaoSocial+contatoPF; cpf, nome devem ser nulos
  Cenario: OutorgadoDestinatario PJ com campos PF preenchidos
    Dado que uma captacao do tipo DEMANDA_INDUZIDA esta sendo configurada
    E um OutorgadoDestinatario com tipo = PESSOA_JURIDICA e cadastrado
    Quando os campos cpf ou nome sao fornecidos para esse destinatario
    Entao o sistema rejeita o cadastro com mensagem indicando que campos de pessoa fisica nao sao permitidos para pessoa juridica
    E os campos cnpj, razaoSocial e contatoPF sao obrigatorios para tipo PESSOA_JURIDICA

  # RequisitoProponente.exigeVinculoEmpregaticio
  Cenario: Proponente sem vinculo empregaticio em captacao que exige vinculo
    Dado que a captacao possui RequisitoProponente.exigeVinculoEmpregaticio = true
    E o proponente autenticado nao possui vinculo empregaticio ativo registrado no sistema
    Quando o proponente tenta submeter uma proposta para essa captacao
    Entao o sistema rejeita a submissao com mensagem informando que e necessario vinculo empregaticio ativo para participar desta captacao
    E nenhuma proposta e registrada no sistema

  Cenario: Proponente com vinculo empregaticio ativo em captacao que exige vinculo
    Dado que a captacao possui RequisitoProponente.exigeVinculoEmpregaticio = true
    E o proponente autenticado possui vinculo empregaticio ativo registrado no sistema
    Quando o proponente tenta submeter uma proposta valida
    Entao o sistema aceita a submissao normalmente
```
