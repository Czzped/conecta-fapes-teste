## Contexto

Modulos consumidores precisam enviar PDFs de Termos formais para coleta de assinatura juridicamente valida. Hoje, sem M023, os fluxos de formalizacao ficam bloqueados (M009 EPIC-003 explicitamente "A definir"). M023 expoe um comando unico — `EnviarDocumentoParaAssinatura(documentoId, signatarios)` — que abstrai OAuth, upload MinIO, captura inicial assincrona no provedor E-Docs V2 e devolve um `SolicitacaoAssinatura` com `idEdocs` ja registrado e fila de captura inicial concluida.

## Objetivo

Permitir que qualquer modulo consumidor envie um Documento M008 ao provedor de assinatura externo com lista de signatarios e receba uma `SolicitacaoAssinatura` materializada, persistida e em estado `AGUARDANDO_ASSINATURAS`, sem precisar conhecer OAuth, MinIO ou polling.

## Regras de Negocio

RN01, RN02, RN03, RN04, RN10, RN11, RN12, RI2 — ver [Regras de Negocio](../README.md#regras-de-negocio)

## Dependencias

### US-M023-001: Cadastrar adapter de provedor E-Docs V2

Como Sysadmin,
quero configurar credenciais OAuth Client Credentials e endpoints do E-Docs (Treinamento ou Producao),
para que M023 possa autenticar contra o provedor sem expor secrets aos modulos consumidores.

```gherkin
Funcionalidade: Configurar adapter E-Docs

  Cenario: Configuracao bem-sucedida (Treinamento)
    Dado que o Sysadmin esta autenticado no Portal Admin
    E informa client_id, client_secret e ambiente=Treinamento
    Quando salva a configuracao
    Entao o sistema valida obtendo um token via POST /is/connect/token
    E persiste a configuracao com status "ATIVA"

  Cenario: Credenciais invalidas
    Dado que o Sysadmin informa client_id ou secret invalidos
    Quando tenta validar
    Entao o sistema rejeita com mensagem de erro do Acesso Cidadao
    E nao persiste a configuracao

  Cenario: Mudanca de ambiente Treinamento -> Producao
    Dado que existe configuracao ATIVA para Treinamento
    Quando o Sysadmin muda para Producao com novas credenciais
    Entao o sistema valida o novo token
    E SolicitacaoAssinatura abertas em Treinamento permanecem com a configuracao anterior por referencia

  Cenario: Cache de token
    Dado que existe token valido nao expirado
    Quando uma requisicao precisa de token
    Entao o sistema reusa o token existente
    E nao chama POST /is/connect/token desnecessariamente
```

### US-M023-002: Enviar Documento para coleta de assinaturas

Como modulo consumidor (M009/M022/M003/M010),
quero enviar um Documento M008 com lista de signatarios para coleta de assinaturas,
para que o documento entre no fluxo de assinatura sem que eu precise conhecer detalhes de OAuth, MinIO ou captura.

```gherkin
Funcionalidade: Enviar Documento para Assinatura

  Cenario: Envio bem-sucedido com 5 signatarios (Termo de Compromisso M009)
    Dado que existe Documento DOC-2026-001 em estado CRIADO no M008 com PDF de 800 KB
    E os signatarios sao Coordenador, Orientador, Bolsista, DIRAF, DIPRE (todos PessoaFisica cadastrada)
    Quando o M009 chama POST /api/v1/m023/solicitacoes-assinatura com documentoId e signatarios[]
    Entao o sistema:
      - autentica via Client Credentials
      - chama GET /v2/documentos/upload-arquivo/gerar-url-upload/{tamanho}
      - faz POST multipart no MinIO com idArquivo retornado
      - chama POST /v2/documentos/capturar/nato-digital/auto-assinado/servidor com assinantes
      - persiste SolicitacaoAssinatura SOL-2026-001 em estado ENVIADA
      - persiste 5 Signatario em estado PENDENTE
      - registra EventoAssinatura tipo=CAPTURA_INICIAL
    E retorna 201 Created com idSolicitacao + idEventoCapturaInicial

  Cenario: PDF invalido (sem texto pesquisavel)
    Dado que o Documento DOC-2026-002 tem PDF apenas com imagem (sem OCR)
    Quando o M009 envia para assinatura
    Entao o sistema rejeita com 422 e codigo DOCUMENTO_INVALIDO_PDF
    E nao cria SolicitacaoAssinatura

  Cenario: PDF excede 250 MB
    Dado que o Documento tem PDF de 300 MB
    Quando o M009 envia
    Entao o sistema rejeita com 422 e codigo DOCUMENTO_EXCEDE_LIMITE

  Cenario: Solicitacao duplicada
    Dado que ja existe SolicitacaoAssinatura em estado AGUARDANDO_ASSINATURAS para DOC-2026-001
    Quando o M009 envia outra solicitacao para o mesmo documento
    Entao o sistema retorna 409 SOLICITACAO_DUPLICADA com idSolicitacao existente (idempotencia)

  Cenario: E-Docs indisponivel
    Dado que o E-Docs retorna 503 ao chamar gerar-url-upload
    Quando o M009 envia
    Entao o sistema retorna 503 PROVEDOR_INDISPONIVEL
    E nao cria SolicitacaoAssinatura
    E modulo consumidor pode tentar novamente

  Cenario: Captura inicial demora alem de 1 hora
    Dado que SolicitacaoAssinatura SOL-2026-001 esta em estado ENVIADA
    E o evento de captura inicial nao retorna `Executado` em 1 hora
    Quando o job de polling executa
    Entao o sistema marca SOL-2026-001 como ERRO
    E emite ErroIntegracaoAssinatura
```

### US-M023-003: Persistir SolicitacaoAssinatura, Signatarios e EventoAssinatura

Como M023,
quero persistir localmente toda solicitacao com signatarios e log de eventos,
para que possamos reconstruir auditoria, fazer reconciliacao e oferecer consulta sincrona aos consumidores.

```gherkin
Funcionalidade: Persistencia local

  Cenario: Persistencia apos envio
    Dado um envio bem-sucedido com 5 signatarios
    Quando captura inicial concluir
    Entao existe 1 SolicitacaoAssinatura, 5 Signatario e 2 EventoAssinatura
      (envio + captura inicial executada)
    E todos os atributos derivados (totalAssinantes=5, totalAssinados=0, dataExpiracao=dataEnvio+30d) estao corretos

  Cenario: Idempotencia do EventoAssinatura
    Dado que o job de polling consulta o mesmo evento duas vezes
    Quando processa a segunda vez
    Entao verifica EventoAssinatura.idEventoExterno e marca processado=true apenas uma vez
    E nao reemite eventos publicos
```

## Cenarios negativos cross-US

```gherkin
  Cenario: Documento inexistente
    Dado que documentoId aponta para registro inexistente em M008
    Quando o consumidor envia
    Entao o sistema retorna 404 DOCUMENTO_NAO_ENCONTRADO

  Cenario: Signatarios com pessoa inexistente
    Dado que pessoaId nao existe em M008.PessoaFisica
    Quando o consumidor envia
    Entao o sistema retorna 400 SOLICITACAO_DADOS_INVALIDOS com lista de pessoas invalidas
```
